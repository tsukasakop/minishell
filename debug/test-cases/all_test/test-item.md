### ビルドイン pwd
- カレントディレクトリの実行権限がない時に、pwdが表示されない→修正必要。修正に時間がかかる場合は、権限系のバグ全てを仕様として未定義にする(したい)。
```bash
mkdir /tmp/hoge
cd /tmp/hoge
chmod -x /tmp/hoge
pwd
```
### ビルドイン　cd
- カレントディレクトリの実行権限がない時に、`../`で移動ができない。(`.`や絶対パスでの移動はできる)

- PWD, OLDPWDをunset後、これらを使った移動ができない→環境変数の更新を行わないため、未対応にする。

- 親ディレクトリの実行権限がない場合のエラー出力や、パスの変化が起きない

### ビルドイン　exit
- exit実行後の環境変数が正しくない
- 不正な引数(不正な符号、LONG_MAX以上/LONG_MIN以下、数字以外、小数点)だった場合のエラー文が出ない

### コマンド
- 空行、空白で実行した時の終了ステータスが異なる
→本来は最後に実行したコマンドの終了ステータスだが、毎回0にリセットされる

- クォートのみで実行した際、エラー文がなぜか"Permission denied"になる。終了ステータスも異なる(本来は127だが、現在は126)
→ MUSTで修正。Parseとコマンド実行でどう処理されているかを確認する必要がある

- 実行権限がない状態でコマンドを実行した時、エラー文にpathが出ない
→そこまで合わせる必要性がないので現状のままにする

- unset PATH後、クォートのみで実行した際、エラー文にbash: :の空白が出力されない
→そこまで合わせる必要性がないので現状のままにする


### 数字+リダイレクト
- リダイレクト左側数字(以下、n)がINT_MAXを超えた場合、の挙動がbashと異なる。(bashの場合、コマンドの引数として受け取られるが、現状のminishellでは"Bad file descriptor"として扱われる)
→そこまで対応する必要ないのでは？

- nが0の時、fd0にリダイレクトされない
→要修正。だが、そもそも左側の数字は見られない場合が多いので、優先度は低い。
